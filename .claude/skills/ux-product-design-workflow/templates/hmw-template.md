# How Might We (HMW) Statement Template

## HMW Statement

> **How might we** [action verb] + [user segment] + [desired outcome] + [context/constraint]?

---

## HMW Construction

### Core Components

| Component | Description | Example |
|-----------|-------------|---------|
| **Action Verb** | What action we're exploring | Help, Enable, Support, Guide, Empower |
| **User Segment** | Who we're designing for | First-time users, Power users, Elderly users |
| **Desired Outcome** | What success looks like | Feel confident, Save time, Avoid errors |
| **Context/Constraint** | Relevant situation | Within 5 minutes, On first use, During checkout |

---

## Calibration Check

### The Goldilocks Test

| Assessment | Status | Notes |
|------------|--------|-------|
| **Not Too Broad** | ✓/✗ | [Does it suggest too many directions?] |
| **Not Too Narrow** | ✓/✗ | [Does it constrain solutions too much?] |
| **Just Right** | ✓/✗ | [Does it open creative solution space?] |

### Examples

| Type | HMW Statement | Assessment |
|------|---------------|------------|
| **Too Broad** | "HMW make the app better?" | Opens too many directions; no focus |
| **Too Narrow** | "HMW add a blue notification badge?" | Assumes solution; constrains creativity |
| **Just Right** | "HMW help new users feel confident completing their first transaction within 5 minutes?" | Specific enough to act on; opens multiple solutions |

---

## HMW Variations

### Version 1: Standard Format
> How might we **[action]** **[user segment]** to **[desired outcome]**?

### Version 2: With Context
> How might we **[action]** **[user segment]** to **[desired outcome]** when **[situation]**?

### Version 3: With Constraint
> How might we **[action]** **[user segment]** to **[desired outcome]** without **[pain point to avoid]**?

## HMW Quality Checklist

- [ ] Starts with "How might we"
- [ ] Uses action verb (help, enable, support, etc.)
- [ ] Identifies specific user segment
- [ ] States desired outcome from user perspective
- [ ] Not too broad (not "make it better")
- [ ] Not too narrow (not "add a button")
- [ ] Opens multiple solution possibilities
- [ ] Grounded in research evidence
- [ ] Actionable by the team
