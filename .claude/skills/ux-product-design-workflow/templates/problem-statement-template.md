# Problem Statement Template

## Problem Statement

> **[User segment]** needs a way to **[need]** because **[insight]**.

**What does the user need (not a feature)?**

| Attribute | Description | Evidence |
|-----------|-------------|----------|

**Quality Check:**
- [ ] This is a need, not a feature request
- [ ] This is specific, not vague

## Full Problem Statement Variations

### Version 1: Standard Format
> **[User segment]** needs a way to **[need]** because **[insight with evidence]**.

### Version 2: With Context
> When **[situation]**, **[user segment]** needs a way to **[need]** because **[insight with evidence]**, but currently **[current workaround/friction]**.

### Version 3: With Impact
> **[User segment]** needs a way to **[need]** because **[insight]**. This affects **[number/frequency]** users and results in **[business impact]**.

## Examples

### Good Problem Statement
> First-time mobile wallet users in Egypt need a way to understand transaction fees upfront because hidden costs at checkout cause 43% abandonment and erode trust in digital payments.

**Why it's good:**
- Specific user segment
- Real need (understanding, not a feature)
- Evidence-backed insight
- Business relevance clear

### Bad Problem Statement
> Users need a better checkout experience.

**Why it's bad:**
- Vague user segment ("users")
- Need is vague ("better")
- No insight or evidence
- Not actionable
