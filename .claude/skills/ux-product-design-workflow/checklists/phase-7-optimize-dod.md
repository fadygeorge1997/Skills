# Phase 7: Post-Launch Optimization — Definition of Done

## Overview

This checklist defines the criteria for establishing a healthy optimization rhythm. Phase 7 is ongoing, but this checklist ensures the foundation is properly set.

---

## Checklist

### HEART Framework Setup

- [ ] Happiness goals, signals, and metrics defined
- [ ] Engagement goals, signals, and metrics defined
- [ ] Adoption goals, signals, and metrics defined
- [ ] Retention goals, signals, and metrics defined
- [ ] Task Success goals, signals, and metrics defined
- [ ] All metrics have targets and baselines

### AARRR Funnel Analysis

- [ ] Acquisition funnel stages mapped
- [ ] Activation funnel stages mapped
- [ ] Retention cohort analysis set up
- [ ] Referral tracking in place
- [ ] Revenue metrics tracked
- [ ] Drop-off hypotheses documented

### Goals-Signals-Metrics

- [ ] Goals defined for each feature/initiative
- [ ] Success signals identified
- [ ] Failure signals identified
- [ ] Metrics mapped to signals
- [ ] Targets set for each metric
- [ ] Current baselines recorded

### North Star Metric

- [ ] North Star Metric defined
- [ ] NSM meets criteria (expresses customer value, reflects engagement, leading indicator)
- [ ] Input metrics identified
- [ ] Counter-metrics defined
- [ ] Targets set (3-month, 6-month, 12-month)

### Experiment Backlog

- [ ] Hypotheses generated from data and feedback
- [ ] Experiments prioritized by impact/effort
- [ ] Success criteria defined for each experiment
- [ ] Guardrail metrics identified
- [ ] Minimum 5 experiments in backlog

### Monitoring & Alerts

- [ ] Monitoring dashboard created
- [ ] Automated anomaly alerts configured
- [ ] Weekly metrics review scheduled
- [ ] Owner assigned for each metric

### Continuous Discovery

- [ ] Weekly customer touchpoint scheduled
- [ ] Opportunity backlog maintained
- [ ] Learnings fed back to discovery phase
- [ ] Research-to-design-to-dev loop documented

### Product Kata

- [ ] Direction set (north-star alignment)
- [ ] Current state documented
- [ ] Target condition defined (2-4 week goal)
- [ ] Weekly experiment cadence established
- [ ] Learning documentation process defined

## Quality Assurance

### Metrics Quality Check

| Check | Status |
|-------|--------|
| Metrics measure user outcomes (not features) | ✓/✗ |
| Targets are realistic and time-bound | ✓/✗ |
| Baselines established | ✓/✗ |
| Counter-metrics defined to prevent gaming | ✓/✗ |

### Experiment Quality Check

| Check | Status |
|-------|--------|
| Hypotheses follow format: "We believe [change] will [outcome] because [evidence]" | ✓/✗ |
| Success criteria defined before running | ✓/✗ |
| Guardrail metrics protect against harm | ✓/✗ |
| Minimum 2-week duration for A/B tests | ✓/✗ |

---

## Warning Signs (Revisit if)

- Metrics are vanity metrics (total signups, not active users)
- No counter-metrics defined
- Experiments running without success criteria
- No weekly customer contact
- Optimizing metrics at expense of user experience

---

---

## Loop-Back Triggers

- D7 retention <20% → loop back to Phase 1 for fundamental research
- 3+ A/B tests with no significant lift → loop back to Phase 2 to reframe hypothesis
- New user segment discovered in analytics → loop back to Phase 1 for targeted research
- Support tickets cluster around a specific flow → loop back to Phase 5 for targeted testing
- Funnel drop-off >50% at a specific step → loop back to Phase 3 or 4 for redesign

---

## Looping Back

When new user needs emerge or metrics stall:

The product development cycle is continuous. Every optimization insight should feed back into discovery.
